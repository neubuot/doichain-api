Die Doichain per HTTP.
Nachweise, Namen, Kette.

Eine Schnittstelle, mit der jedes Programm die Doichain nutzt, ohne eigene Node und ohne JSON-RPC: Proof of Existence anlegen und prüfen, Namen mit name_doi registrieren, Blöcke, Transaktionen und Adressguthaben abfragen. Lesen ist frei, Schreiben braucht einen Schlüssel.

Was die API kann

Alle Doichain-Funktionen in acht Gruppen, jede Antwort als JSON mit fertigen Explorer-Links.

✓

Proof of Existence

SHA-256 einer Datei als Name poe/<hash> verankern und prüfen: GET /v1/poe/{hash}, POST /v1/poe, Datei-Upload optional.

⌘

Namen und name_doi

Lesen, durchsuchen, Historie, registrieren, verlängern, übertragen: /v1/name/…, /v1/names, POST /v1/name/doi.

⛓

Kette

Blöcke, Transaktionen mit dekodierten Namensoperationen, Mempool, Netzwerk: /v1/blocks, /v1/block/{id}, /v1/tx/{txid}.

◎

Adressen

Guthaben, Historie und UTXOs beliebiger Adressen (N…, 6…, dc1q…) über den lokalen ElectrumX.

▣

Wallet

Guthaben, Adressen, Auszahlungen mit fester Gebührenrate, nur mit Schlüssel: /v1/wallet/….

⚙

Werkzeuge

Adressen prüfen, Nachrichten signieren und prüfen, Gebührenempfehlung, generischer RPC-Durchgriff mit Sperrliste.

✦

KI-Agenten (MCP)

Claude, ChatGPT, Cursor und andere Agenten nutzen die Doichain über den MCP-Server unter /mcp: verankern, prüfen, Namen lesen. Einbinden

♥

Betrieb

/health meldet nur dann ok, wenn die Kette synchron ist und die Fork-Prüfung stimmt. Einheitliches Fehlerformat, OpenAPI 3.1.

Spielwiese

Lesende Aufrufe direkt gegen die laufende Node, ohne Schlüssel. Die Antwort kommt live von der Doichain.
